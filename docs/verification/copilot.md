# GitHub Copilot CLI worker verification

Audience: maintainer verification.

Verified 2026-10-14 on Linux x64 in the dev container with `GitHub Copilot CLI 1.0.97.` and tmux 3.5a.
The [adapter reference](../../.agents/skills/harness-adapters/references/harness/copilot.md) owns operating facts; executable owners carry launch and state mechanics.
This verification covers crewmates and scouts, with tmux as the exercised runtime backend.
Primary-session evidence is recorded separately in [supervision verification](supervision.md); secondmate, Herdr, and quota-provider integration are outside this guarantee.

## Refresh commands

```sh
copilot --version
copilot --help
copilot help config
bin/fm-test-run.sh tests/fm-copilot-harness.test.sh
FM_COPILOT_SIGNALS_LIVE=1 bin/fm-test-run.sh tests/fm-copilot-signals-live-e2e.test.sh
```

The credentialed guard keeps the operator's real Copilot sign-in, uses a private tmux socket, and runs the actual command generated by `fm-spawn.sh`.
Its pane inherits a Copilot primary's `COPILOT_CLI`, `COPILOT_AGENT_SESSION_ID`, and `COPILOT_CLI_RUN_AS_NODE` values, and the worker must report its own session id instead.
Worktree allocation and initial endpoint delivery use the portable fixture; steering and lifecycle control then use the real backend and vendor process.
`FM_COPILOT_MODEL` overrides its `claude-haiku-4.5` default; the shared live gate owns absent-tool and opt-in behavior.
Failures name the installed Copilot version.

## Observed vendor surfaces

The idle composer is a bare `❯` between two solid `─` rules with no placeholder, above the footer `← open sidebar · Interactive · Allow All · / commands · ? help · tab next tab`.
The status footer reads `● Working esc edit prompt` before output streams and `◎ Working · 108 B esc interrupt` after, with a rotating `◎ ○ ◉ ●` spinner.
One Esc on a streaming turn renders `esc again to interrupt` for about 0.6 seconds; a second press inside that window prints `Operation cancelled by user` above an empty composer.
One Esc in the `esc edit prompt` phase renders `esc again to edit prompt`; a second press cancels the turn and restores its prompt into the composer.
One Esc on an idle agent renders `esc again to rewind`; idle pairs 0.1, 0.3, 0.4, and 0.45 seconds apart opened the "Rewind to a previous point" picker, and pairs 0.5 seconds or more apart did not.
That picker's footer reads `↑↓ Navigate · Enter Select · Esc Cancel`, and one Esc closes it without rewinding.
Two Esc presses with no gap at all were read as one key sequence and opened nothing.

Without `COPILOT_ALLOW_ALL=true`, a fresh repository showed a "Confirm folder trust" dialog even under `--allow-all`, and no hook fired until it was answered.
A legacy plugin mounted with `--plugin-dir` ran hooks declared inline as `{"hooks": {...}}` or through a `hooks.json` path, and ignored the same hooks nested under a `{"version": 1, "hooks": {...}}` wrapper.
Hook payload keys observed were `cwd`, `prompt`, `sessionId`, and `timestamp` for `userPromptSubmitted`; `cwd`, `sessionId`, `stopReason` (`end_turn`), `stop_hook_active`, `timestamp`, and `transcriptPath` for `agentStop`; and `cwd`, `reason` (`complete` or `user_exit`), `sessionId`, and `timestamp` for `sessionEnd`.
For an `-i` launch, `userPromptSubmitted` fired before `sessionStart`.
A cancelled turn emitted no `agentStop`.

A message submitted during a running turn appeared in the transcript at once and cleared the composer, while `/exit` typed during a running turn was shown as `Queued (1)` and did not exit.
Both the node launcher and the native engine reported the kernel process name `MainThread`; the engine's argv[0] was its install path ending in `@github/copilot-linux-x64/copilot`.
`--reasoning-effort max` with `gpt-5-mini` failed a `-p` run with `Reasoning effort "max" is not supported for model "gpt-5-mini".`, while the interactive TUI printed the same line and continued at the model default.
`copilot help config` listed the account's selectable model ids under `model`; model availability is an observation of this account and date, not an adapter-maintained catalog.
